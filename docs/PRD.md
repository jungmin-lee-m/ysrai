## 1. 개요

### 1.1 배경
의원·병원의 의료진은 진료 중 차팅(SOAP 작성), 상병·처방 입력, 환자 이력 파악, 환자 교육 자료 작성 등 반복적·소모적인 행정 업무에 많은 시간을 쓴다. **의사랑 AI**는 의사랑 EMR과 연동되는 데스크톱 진료 보조 AI로, 진료 대화를 자동으로 기록·요약하고 의사랑 데이터를 기반으로 의사결정을 돕는다.

### 1.2 제품 비전
> "진료에만 집중할 수 있도록, 기록과 조회는 AI가 처리한다."

### 1.3 핵심 가치
- **자동 기록**: 진료 대화를 음성 인식(STT)하여 SOAP·상병·처방을 자동 생성
- **맥락 있는 보조**: 의사랑에 쌓인 환자 과거 차트·통계 데이터를 근거로 추천·답변
- **단계적 도입**: 의사랑 미연동 상태에서도 STT·SOAP는 즉시 사용 가능 → 연동 시 전체 기능 확장

## 3. 제품 구조 — 두 개의 핵심 기능

의사랑 AI는 크게 **두 가지 기능**으로 나뉜다. 첫 진입(랜딩) 시 사용자가 둘 중 하나를 선택한다.

| 기능 | 정의 | 핵심 산출물 |
|---|---|---|
| **AI 진료** (STT) | 진료 대화를 녹음·전사하여 진료 기록을 자동 생성 | 음성기록 → SOAP → 상병/처방 추천 |
| **대화** | AI에게 일반 의학 질문 또는 의사랑 데이터 기반 통계/분석 질의 | 답변, 교육 자료, 통계 |

## 4. 상태 모델 (Prototype 토글)

제품 동작은 두 개의 독립 상태에 따라 달라진다. 프로토타입에서는 타이틀바 토글로 상태를 임의 전환해 각 화면을 검증할 수 있다.

| 상태 | 값 | 의미 |
|---|---|---|
| 의사랑 연동 | 연동 / 미연동 | 의사랑 EMR 데이터 접근 가능 여부 |
| 진료실 실행 | 실행 / 미실행 | (연동 시) 진료실 프로그램 실행 여부 — **대기 환자 목록 노출 조건** |

### 4.1 상태별 가용 기능 매트릭스

| 기능 | 미연동 | 연동 + 진료실 미실행 | 연동 + 진료실 실행 |
|---|:---:|:---:|:---:|
| STT 음성기록 | ✅ | ✅ | ✅ |
| SOAP 자동 생성 | ✅ | ✅ | ✅ |
| 대기 환자 목록(대기/예약/완료) | ❌ | ❌ | ✅ |
| 환자 진료이력 요약 | 🔒 | ✅ | ✅ |
| 상병/처방 추천 (과거 차트 기반) | 🔒 | 환자 지정 시 ✅ | 환자 지정 시 ✅ |
| 대화 (일반·의사랑 데이터) | 🔒 | ✅ | ✅ |

> ✅ 사용 가능 · 🔒 잠금(연동 안내 표시) · ❌ 비노출

핵심 규칙:
- **미연동**: 환자 대기 목록·요약·상병/처방·대화는 잠금. 단 **환자 미지정 상태의 STT + SOAP**는 사용 가능.
- **연동했어도 진료실 미실행**: 대기 환자 목록이 표시되지 않음 → 상단 "녹음 시작"으로 환자 미지정 진료만 가능.
- **연동 + 진료실 실행**: 전체 기능 + 대기 환자 목록.

## 5. 기능 요구사항

### 5.1 랜딩 페이지
- "무엇을 도와드릴까요?" 인사 + 현재 상태 Pill(의사랑 연동 / 진료실 실행)
- 두 개의 액션 카드: **AI 진료**, **대화**
- 미연동 시 카드에 제약 안내(예: "AI 진료 — 미연동: STT·SOAP만", "대화 — 미연동: 사용 불가")
- 로고 클릭 시 언제든 랜딩으로 복귀
- 좁은 화면에서 카드 중앙 정렬, 넓은 화면에서 가로 배치(동일 높이)

### 5.2 AI 진료

#### 5.2.1 좌측 패널 — 녹음 컨트롤 & 환자 목록
- **상단 녹음 바 (2상태)**
  - *녹음 아님*: `녹음 시작` 버튼
    - 대기 환자가 있으면 → **환자 선택 팝업** (대기 환자 목록 + "환자 미지정으로 시작")
    - 대기 환자가 없으면 → **환자 미지정**으로 즉시 녹음 시작
  - *녹음 중*: 파형 + 녹음 대상 환자명 + 타이머 → **클릭 시 해당 환자 녹음 화면으로 전환**
- **상위 탭**: 대화 / AI 진료
- **진료 날짜 + 달력**
  - 목록 상단에 진료 날짜 표시(요일 포함), 클릭 시 달력 팝오버
  - 과거 날짜 선택 가능(미래 비활성), 과거 날짜 → **완료 섹션**만 펼침, 오늘 → **대기 섹션**만 펼침
  - 오늘이 아닐 때만 "오늘" 버튼 노출(클릭 시 오늘로 복귀)
- **환자 목록 (섹션)**: 대기 / 예약 / 완료 (아코디언)
  - 환자 행: 차트번호 · 이름 · 나이/성별 · (신환) · 상태 뱃지
  - 완료 섹션: 수납대기/수납완료 뱃지(약한 배경, 무채색)
  - 행 호버 시 `호출하기` 버튼 노출(미연동 시 잠금)
  - 환자 이름은 폭이 좁아져도 잘리지 않음(성별/나이가 먼저 축약)
- **반응형(컴팩트 모드)**: 패널 폭을 줄이면(< 약 212px) 상태 뱃지가 **첫 글자 칩**으로, 보험/메모 등 정보가 축약, 날짜는 연도 생략
- **접기**: 패널을 접으면 좁은 레일에 녹음 상태가 계속 표시되고, 레일 호버 시 전체 패널이 콘텐츠 위로 슬라이드 노출

#### 5.2.2 중앙 패널 — 진료 화면
- **환자 정보 헤더**: 현재 *보고 있는* 환자(차트번호·이름·나이/성별·보험·메모)
- **중앙 녹음 세션 바 (보는 환자 기준)**
  - 보는 환자가 녹음 대상이 아니고 녹음도 없을 때 → `녹음 시작`(그 환자 녹음 시작)
  - 보는 환자를 녹음 중 → 파형 + 환자명 + 타이머 + **중지(종료)**
  - **다른 환자가 녹음 중**일 때 → "다른 환자 녹음 중 · {환자명}" 알림 + **중지** + **클릭 시 그 환자 화면으로 이동**
- **진료이력 요약**(연동 시), **SOAP**(녹음 완료 시), **상병/처방**(환자 지정 시)

#### 5.2.3 녹음 세션 워크플로우 (핵심 규칙)
녹음은 **특정 환자에 묶인 세션**으로 동작하며, "보고 있는 환자"와 분리된다.

| 행동 | 결과 |
|---|---|
| 환자 행 **클릭(보기)** | 녹음 **계속 유지**(녹음 대상 환자 불변), 중앙은 보는 환자 화면으로 전환 |
| 다른 환자 **호출** | 기존 녹음 **중단하고 새 환자로 재시작**(타이머 0:00) |
| 좌측 바 환자명 / 중앙 "다른 환자 녹음 중" 클릭 | **녹음 중인 환자 화면으로 점프** |
| **중지** | 녹음 완료 + **그 환자의 SOAP 생성 화면으로 전환** |

#### 5.2.4 SOAP / 상병 / 처방
- **SOAP**: S/O/A/P 4섹션, 컴팩트 줄간, 액션(다시 생성 · 복사 · 의사랑에 전송)
- **상병/처방 추천**: 환자 **과거 차트에 포함된 적 있는 내용**만 추천 → 각 항목에 **출처 차트 날짜** 표시
  - 접기/펼치기 없이 컴팩트, 항목 클릭 시 전송/전송됨 토글
  - **환자 미지정 녹음 시 미노출**(과거 차트 근거가 없으므로)
- 미연동 시 상병/처방은 잠금(연동 안내)

#### 5.2.5 진료이력 요약
- 환자 진료이력을 자동 분석한 위젯 대시보드(약물·관찰·검사·시술·예방접종 등), masonry 2단 배치
- 버블 내부 단일 스크롤(위젯별 중첩 스크롤 없음)
- 연동 시에만 표시(미연동 시 잠금 안내)

### 5.3 대화
- **성격**: 현재 환자 컨텍스트 기반이 아닌, ①일반 GPT식 의학 질문 + ②의사랑 데이터 기반 통계/분석
- **히스토리**: 날짜별 그룹(오늘 / 어제 / 지난 7일 / 지난 30일 / 이전)으로 통합 표시(분류·아이콘 없이 제목만)
- **추천 질문 버튼**: 입력창 위에 빠른 실행(예: 교육 자료 생성, 식이요법 추천, 복약 안내문, 운동 요법 추천)
- **AI 진료 중 빠른 질문**: AI 진료 화면에서는 넓은 폭일 때 우측 도킹 대화창, 좁은 폭일 때 우하단 플로팅 버튼으로 **현재 진료 중인 환자 정보 기반** 질의 제공
- 미연동 시 입력 비활성(연동 안내)

## 7. 비기능 요구사항

### 7.1 기술 스택 (프로토타입)
- React 18 + TypeScript + Vite 6
- Tailwind CSS v4, shadcn/ui (로컬 vendoring)
- 라우팅: react-router (단일 화면 기준)
- 배포: GitHub Pages (GitHub Actions)

### 7.2 디자인 시스템
- MediAI 디자인 토큰 사용(서비스 컬러 violet `--bg-service` 등)
- 모든 색/간격/반경은 CSS 변수 토큰 기반

### 7.3 반응형
- 데스크톱 앱 형태(타이틀바 포함), 좌측 패널 폭 가변(약 184–460px)
- 1280px 기준으로 대화창 도킹/플로팅 전환
- 좌측 패널 폭 축소 시 컴팩트 모드

### 7.4 접근성/사용성
- 상태 뱃지 아이콘/첫 글자에 `title`(전체 상태명) 제공
- 녹음 상태는 좌측·중앙 어디서든 일관된 시각 언어(파형 + 환자명 + 타이머)로 표시

## 8. 프로토타입 범위 vs 실제 제품

| 항목 | 프로토타입(현재) | 실제 제품(향후) |
|---|---|---|
| STT/SOAP | 목 데이터(시간 경과에 따라 전사·생성되는 척) | 실시간 음성 인식 + LLM 생성 |
| 상병/처방 추천 | 고정 목 + 더미 차트 날짜 | 의사랑 과거 차트 실데이터 기반 |
| 진료이력 요약 | 단일 목 환자 데이터 | 환자별 실제 이력 분석 |
| 환자 목록/날짜 | 목 데이터(날짜 바꿔도 동일 목록) | 의사랑 연동 실데이터 |
| 의사랑 전송 | UI만(토글) | 실제 EMR 쓰기 연동 |
| 대화 응답 | 고정 답변 | LLM + 의사랑 데이터 검색 |

## 9. Out of Scope / 향후 과제
- 로그인/계정·권한, 의사랑 실제 연동(인증·읽기/쓰기 API)
- 음성 인식 엔진, 화자 분리, 실시간 전사 정확도
- 상병/처방 추천 모델, 통계 질의 백엔드
- 다중 환자 동시 녹음, 녹음 일시정지/이어녹음 실제 동작
- 저장/이력 관리, 환자별 대화 영속화
- 날짜별 환자 목록 실연동, 진료실 실행 상태 실제 감지

## 10. 용어
| 용어 | 의미 |
|---|---|
| 의사랑 | 연동 대상 EMR 시스템 |
| AI 진료 | STT 기반 진료 기록 자동화 기능 |
| SOAP | Subjective/Objective/Assessment/Plan 진료 기록 형식 |
| 보는 환자(viewed) | 중앙 화면에 현재 표시 중인 환자 |
| 녹음 대상 환자(recPatient) | 현재 녹음 세션이 묶인 환자 |
| 환자 미지정 | 환자 선택 없이 진행하는 녹음 세션 |
