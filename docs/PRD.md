## 1. 제품 개요

**의사랑 AI**는 의사랑 EMR과 연동되는 데스크톱 진료 보조 AI다. 진료 환자와 동기화되어 **과거 진료기록을 빠르게 요약**해 주고, 진료 대화를 녹음·전사하여 **SOAP·진단·처방을 자동 생성**한다. 또한 일반 의학 질문과 의사랑 데이터 질의에 답하는 **대화** 기능을 제공한다.

> 한 줄 정의: "환자 과거력은 자동으로 요약하고, 진료 기록은 음성으로 자동 작성한다."

## 3. 핵심 개념 — 두 개의 기능

제품은 **대화**와 **AI 진료** 두 가지로 나뉜다. 좌측 패널 상단 탭으로 전환하며, 첫 진입(랜딩)에서 둘 중 하나를 선택한다.

| 기능 | 한 줄 정의 | 의사랑 연동 |
|---|---|---|
| **AI 진료** | 진료 환자와 동기화 → 과거력 요약 + 음성 진료 기록(STT→SOAP) + 진단/처방 추천·전송 | 진료 환자 데이터 연동 |
| **대화** | 일반 의학 질문 + 의사랑 데이터 질의(자동 판단) | 데이터 질의 시 연동 |

## 4. AI 진료

### 4.1 핵심 가치
1. **과거 진료기록 요약 (1순위 가치)**
   - 의사랑 진료 환자와 동기화되어, 환자 **호출 전·후에 과거력을 빠르게 스캔**하도록 돕는다.
   - 의사가 과거력을 직접 찾아 기재하지 않아도 되므로 **진료기록 작성 시간이 줄고 업무 효율이 향상**된다.
2. **음성 진료 기록 (STT → SOAP)**
   - 환자 **호출과 동시에 녹음 시작** → 진료 대화를 STT로 전사 → **녹음 종료 시 SOAP 자동 작성**.
3. **진단·처방 추천 및 원클릭 전송**
   - 환자의 **과거 진단·처방 중 오늘 진료 내용과 맞는 항목을 추려 "리피트(재처방)" 후보**로 제시.
   - 작성된 SOAP와 진단/처방 후보는 **원클릭으로 의사랑에 전송**.

### 4.2 표준 진료 워크플로우
```
환자 호출 ─▶ (자동) 녹음 시작 + 과거력 요약 표시
        ─▶ 진료 대화 STT 실시간 전사
        ─▶ 녹음 종료 ─▶ SOAP 자동 생성
        ─▶ 과거 진단/처방 기반 리피트 후보 제시
        ─▶ SOAP·진단·처방 원클릭으로 의사랑 전송
```

### 4.3 환자 목록 (의사랑 대기리스트 연동)
- 의사랑 대기리스트와 동기화된 환자 목록을 **날짜별**로 표시한다.
- 목록은 **대기 / 예약 / 완료** 세 섹션(아코디언)으로 구성.
- **날짜 기본값 = 오늘**, 달력으로 과거·미래 날짜 이동 가능.
- 선택 날짜에 따라 **기본 펼침 섹션**이 달라진다.

| 선택 날짜 | 기본 펼침 섹션 | 의도 |
|---|---|---|
| 오늘(기본) | **대기** | 지금 진료할 환자 |
| 과거 | **완료** | 지난 진료 환자 조회 |
| 미래 | **예약** | 예정된 환자 확인 |

- 환자 행: 차트번호 · 이름 · 나이/성별 · (신환) · 상태. 완료 환자는 수납 상태(수납대기/수납완료) 표시.
- 행 호버 시 **호출하기** 버튼 노출.

### 4.4 좌측 패널
- **상단 탭**: 대화 / AI 진료
- **상단 녹음 시작 상태바** (공통, [§6 참조](#6-녹음-시작-상태바-공통))
- **AI 진료 탭 콘텐츠**: 진료 날짜(달력) + 환자 목록(대기/예약/완료)
- **패널 접기/펴기**
  - 패널을 접을 수 있으며, **접은 상태에서도 녹음 상태(녹음 중/대기)가 레일에 표시**된다.
  - 접힌 레일에 **마우스를 호버하면 좌측 패널이 기존 화면 위로(왼쪽에서) 슬라이드**되어 나온다.
  - → 화면 폭이 좁을 때도 목록에 빠르게 접근해 환자를 호출할 수 있다.
- **반응형(컴팩트)**: 패널 폭을 좁히면 상태 뱃지가 축약되고 부가 정보가 생략된다(환자 이름은 유지).

### 4.5 중앙 진료 화면
보고 있는 환자 기준으로 다음을 표시한다.
- **환자 정보 헤더** (차트번호·이름·나이/성별·보험·메모)
- **녹음 세션 바** (보는 환자 기준, [§4.6 참조](#46-녹음-세션-규칙))
- **과거 진료기록 요약** — 환자 진료이력을 자동 분석한 위젯(약물·관찰·검사·시술·예방접종 등)
- **SOAP** — 녹음 완료 시 생성. 다시 생성 / 복사 / **의사랑 전송** 액션
- **진단·처방 추천** — 과거 차트 기반 리피트 후보, 각 항목에 **출처 차트 날짜** 표기, 항목별 전송. 환자가 지정된 경우에만 표시(환자 미지정 진료에는 미표시)

### 4.6 녹음 세션 규칙 (핵심)
녹음은 **특정 환자에 묶인 하나의 세션**으로 동작하며 "보고 있는 환자"와 분리된다.

| 상황 / 행동 | 동작 |
|---|---|
| 환자 호출 | 해당 환자로 녹음 자동 시작 |
| 녹음 중 다른 환자 **클릭(보기)** 또는 다른 대화로 이동 | 녹음은 **그대로 유지**(대상 환자 불변) |
| 녹음 중 상태바(좌측/중앙) 클릭 | **녹음 중인 환자 화면으로 복귀** |
| 상단 녹음 상태바에서 중지 | 녹음 종료 → 그 환자의 **SOAP 화면으로 전환** |
| 녹음 중 **다른 환자 호출** | **확인 안내**: "○○○ 환자 진료 녹음을 중단하고 ○○○ 환자 진료 녹음을 시작하시겠습니까?" → 확인 시 기존 중단·새 녹음 시작 |

- 중앙 녹음 세션 바는 보는 환자가 녹음 대상이 아닐 때 **"다른 환자 녹음 중 · ○○○"** 으로 알리고, 클릭 시 그 환자로 이동, 중지도 가능하다.

### 4.7 대화창 (AI 진료 화면 내)
- AI 진료 화면에서도 **대화** 기능을 함께 사용할 수 있다(현재 진료 중인 환자 컨텍스트 기반).
- **화면 폭이 충분히 넓으면 우측 패널로 대화창 표시**, **폭이 좁아지면 우측 하단 플로팅 버튼**으로 전환.
- 대화 입력창 **바로 위에 빠른 질문 버튼**(예: "교육 자료 생성", "식이요법 추천") 제공. *버튼 내용은 추후 보완.*

## 5. 대화

### 5.1 두 가지 역할 (자동 판단)
사용자는 **영역을 구분하거나 지정하지 않고** 대화창에 무엇이든 질문하면 된다. 시스템이 질문 성격을 판단해 다음 중 하나로 처리한다.
1. **일반 질문 응답** — GPT처럼 일반 의학/업무 질문에 답변
2. **의사랑 데이터 질의** — 질문을 **SQL로 변환해 의사랑 데이터를 추출**하여 답변(통계·현황 등)

### 5.2 대화 탭 구성
- 상단에 **새 대화** 버튼
- 대화 내역은 **기간별**로 누적·표시: **오늘 / 어제 / 지난 7일 / 지난 30일 / 이전**

## 6. 녹음 시작 상태바 (공통)

대화·AI 진료 탭 **상단에 공통으로 위치**하며 두 역할을 한다.
1. **AI 진료 퀵 시작 버튼** — 누르면 **오늘 대기목록의 환자를 선택**하거나 **환자 미지정**으로 녹음을 시작
2. **녹음 상태바** — 녹음 중일 때 상태(환자명·시간) 표시

- 녹음이 시작되면 **해당 화면으로 자동 전환**: 환자 선택 시 그 환자 진료 화면, 미지정 시 "환자 미지정 녹음 중" 화면.
- 녹음 중에는 이 상태바를 클릭해 **녹음 중인 환자 화면으로 복귀**할 수 있다.

## 7. 랜딩(홈) 페이지
> 문구는 미정, **구조만 확정**.

- 크게 **두 가지 중 하나를 선택**: **AI 진료** / **대화**. 선택하면 해당 탭이 처음 열린다.
- **의사랑 연동 여부**와 **진료실 실행 여부**가 화면 어딘가에 표시된다.

## 8. 상태 모델 (연동 / 진료실)

| 상태 | 값 | 의미 |
|---|---|---|
| 의사랑 연동 | 연동 / 미연동 | 의사랑 EMR 데이터 접근 가능 여부 |
| 진료실 실행 | 실행 / 미실행 | (연동 시) 진료실 실행 여부 — **대기 환자 목록 노출 조건** |

> **상단바의 연동/진료실 토글은 실제 제품 기능이 아니다.** 프로토타입에서 연동 여부·진료실 실행 여부에 따라 화면이 어떻게 달라지는지 확인하기 위한 **개발용 상태 전환 장치**일 뿐이다.

### 8.1 상태별 가용 기능 매트릭스

| 기능 | 미연동 | 연동 + 진료실 미실행 | 연동 + 진료실 실행 |
|---|:---:|:---:|:---:|
| STT 음성기록 / SOAP | ✅ | ✅ | ✅ |
| 대기 환자 목록(대기/예약/완료) | ❌ | ❌ | ✅ |
| 과거 진료기록 요약 | 🔒 | ✅ | ✅ |
| 진단/처방 추천·전송 | 🔒 | 환자 지정 시 ✅ | 환자 지정 시 ✅ |
| 대화 | 🔒 | ✅ | ✅ |

> ✅ 사용 · 🔒 잠금(연동 안내) · ❌ 비노출 — **미연동에서도 환자 미지정 STT·SOAP는 사용 가능**.

## 9. 화면 구조 / 반응형
- 데스크톱 앱 형태(타이틀바 포함). 좌측 패널(탭+목록), 중앙(진료/대화), 우측(대화창, 넓을 때).
- **대화창**: 폭 넓음 → 우측 도킹 패널 / 폭 좁음 → 우측 하단 플로팅 버튼.
- **좌측 패널**: 폭 가변 + 접기/호버 오버레이 + 컴팩트 모드.

## 11. 프로토타입 범위 vs 실제 제품

| 항목 | 프로토타입(현재) | 실제 제품(향후) |

| 환자 목록/날짜 | 목 데이터(날짜 무관 동일) | 의사랑 대기리스트 실연동 |
| 의사랑 전송 | UI만 | 실제 EMR 쓰기 연동 |

## 12. Out of Scope / 향후 과제
- 로그인·권한, 의사랑 실제 연동(인증·읽기/쓰기 API)
- 음성 인식 엔진·화자 분리·실시간 전사 정확도
- 진단/처방 매칭 모델, 의사랑 데이터 질의(NL→SQL) 백엔드
- 녹음 일시정지/이어녹음 실제 동작, 다중 동시 녹음
- 대화 내역 영속화, 환자별 데이터 저장
- 빠른 질문 버튼 콘텐츠 확정

## 13. 프로토타입 반영 현황
개정 기획(v0.2)의 **전 항목이 프로토타입에 반영**되었다.

| 항목 | 상태 |
|---|---|
| 날짜별 목록 펼침 (오늘=대기 / 과거=완료 / **미래=예약**) | ✅ 반영 |
